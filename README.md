## 1. Выбранный объём решения и соответствие ТЗ

### Включённый функционал (60 баллов):
1. **Общие требования к данным и процессам (ТЗ 6.1)**:
   * Реляционная база данных PostgreSQL 16 с ORM SQLAlchemy 2.0 (asyncio, asyncpg) и миграциями Alembic.
   * Схема данных `events` со всеми 29 полями из раздела 8.1 ТЗ (`id` UUID, `normalized_title`, `tags`, `duration_min`, `venue`, `lat`, `lon`, `price_min`, `price_max`, `is_free`, `age_limit`, `language`, `source_url`, `source_type`, `source_hash`, `confidence`, `status`, `dedup_key` и др.).
   * Раздельное хранение нормализованных данных (`events`) и исходных сырых записей (`raw_events`).
   * Нормализованные справочники (`cities`, `categories`, `venues`).
   * **100% идемпотентный импорт CSV и JSON**: повторная загрузка того же файла не создаёт дубликатов.
   * **Дедупликация событий**: сведение одинаковых мероприятий из разных источников (Kassir, Культура.РФ, Яндекс Афиша) в одну карточку с сохранением полного списка подтверждённых первоисточников в таблице `event_sources`.
   * Журнал изменений `audit_logs` (кто, когда и какие поля изменил).
   * Обработка отменённых событий: скрытие из общего каталога, но доступность по прямой ссылке с крупной красной предупреждающей плашкой (ТЗ 6.1).
   * Эталонный набор из **115 реальных культурных мероприятий по 13 городам и районам Башкортостана** с заполненностью полей **100%** (при нормативе ТЗ >= 95%).

2. **Telegram-бот (ТЗ 6.2 — Уровень 1)**:
   * Автономный сервис на Python 3.11+ (aiogram 3.x), работающий в отдельном Docker-контейнере и взаимодействующий с бэкендом исключительно через REST API `httpx.AsyncClient`.
   * Команда `/start` с компактным приветствием и инлайн-кнопками (без «простыни» текста).
   * Команды `/help` и `/cancel` (мгновенный сброс FSM-состояния).
   * Поиск и фильтрация: по названию, городам РБ, категориям, датам (сегодня, завтра, выходные, неделя, конкретная дата) и цене (бесплатные, до указанной суммы).
   * Свободный текст в чате автоматически обрабатывается как поисковый запрос, а при пустом результате бот объясняет причину и предлагает ослабить фильтры.
   * Инлайн-пагинация («Показать ещё ⏩») и возможность начать новый поиск без возврата в `/start`.
   * Подписки на город или категорию и отписка одной командой `/unsubscribe` или кнопкой.

3. **Веб-интерфейс, Виджет и Админка (ТЗ 6.3 — Уровень 2)**:
   * Адаптивный веб-каталог от 360px на FastAPI + Jinja2 + HTMX + Tailwind CSS (CDN) без тяжелых npm-сборщиков.
   * Двусторонняя синхронизация фильтров каталога с URL query-параметрами (ссылкой можно поделиться).
   * Постоянные ссылки на карточку события `/events/{id}` (доступны не более чем в 3 клика от входа).
   * Встраиваемый виджет `/widget` для `<iframe>` и интерактивный конструктор `/widget-demo` с готовым кодом вставки, изолированными стилями и **без сторонних cookies**.
   * Защищённая форма обратной связи для организаторов (honeypot-ловушка + sliding window rate-limiter).
   * Веб-админка `/admin` (HTTP Basic Auth) с модерацией статусов, журналом аудита и загрузкой файлов импорта с подробным отчётом.
   * Версионированный REST API `/api/v1/` с OpenAPI 3.1 (`/docs`), ETag-кешированием (`304 Not Modified`), эндпоинтом `/health`, метриками `/metrics` и структурным логированием без PII.

### Честно исключённый функционал (Уровни 3 и 4):

## 3. Политика приватности и хранение данных (ТЗ 6.1, 6.2)

1. **Минимизация персональных данных**:
   * Сервис не запрашивает и не хранит ФИО, номера телефонов, email или паспортные данные пользователей.
   * Таблица подписок `subscriptions` хранит исключительно числовой идентификатор `telegram_id` и выбранные фильтры (`city`, `category`).
2. **Срок хранения подписок**:
   * По умолчанию активная подписка хранится **180 дней** (`SUBSCRIPTION_RETENTION_DAYS=180`), после чего неактивные подписки архивируются.
   * При отправке команды `/unsubscribe` или нажатии кнопки «Отписаться от всех» подписки пользователя удаляются из базы данных **немедленно**.
3. **Логирование без PII**:
   * В логах веб-сервера IP-адреса клиентов маскируются (`127.0.0.xxx`), персональные данные отсутствуют.
   * Каждый HTTP-запрос снабжается сквозным заголовком `X-Request-ID` (`UUID4`) для наблюдаемости и аудита.

### Основной способ: Docker Compose

1. **Клонируйте репозиторий и перейдите в корень проекта**:
   ```bash
   cd C:\Projects\Hacaton
   ```

2. **Подготовьте файл переменных окружения**:
   ```bash
   cp .env.example .env
   ```
   *(При необходимости укажите ваш токен Telegram-бота в параметре `BOT_TOKEN` в файле `.env`. Если токен не указан, бот запустится в безопасном демонстрационном режиме).*

3. **Запустите сервис одной командой**:
   ```bash
   docker compose up --build
   ```

1. Запуск контейнера СУБД PostgreSQL 16 с healthcheck-проверкой `pg_isready`.

3. Загрузку справочников и **эталонного датасета из 115 событий по Башкортостану** (`python -m scripts.seed_data`).
4. Запуск веб-приложения FastAPI (`http://localhost:8000`) и Telegram-бота.

## 5. Встраиваемый виджет для сайтов (`<iframe>`)

Виджет предназначен для интеграции афиши на официальные порталы муниципальных районов, министерств и домов культуры.

### Характеристики (ТЗ 6.3):
* Полная изоляция стилей от страницы-контейнера.
* **Строго без сторонних cookies** и счетчиков слежения.
* Адаптивен по ширине от 320px.
* Поддерживает фильтрацию через URL:
  * `city` — город (например: `?city=Уфа` или `?city=Стерлитамак`)
  * `category` — категория (`?category=спектакль`, `?category=концерт`)
  * `period` — период (`?period=today`, `?period=weekend`, `?period=week`)

### Готовый HTML-код для вставки:
```html
<iframe 
    src="http://localhost:8000/widget?city=Уфа&category=спектакль" 
    width="100%" 
    height="540" 
    frameborder="0" 
    style="border: none; border-radius: 12px; overflow: hidden; max-width: 580px;" 
    title="Афиша культуры Башкортостана">
</iframe>
```

## 6. Примеры работы с REST API (`curl`)

### 1. Получение списка событий с фильтрами и пагинацией:
```bash
curl -X GET "http://localhost:8000/api/v1/events?city=Уфа&category=спектакль&page=1&size=5" \
     -H "Accept: application/json"
```

### 2. Проверка кеширования ETag (возврат `304 Not Modified`):
```bash
# Первый запрос возвращает заголовок ETag:
curl -i "http://localhost:8000/api/v1/events?city=Уфа"

# Повторный запрос с If-None-Match вернет HTTP 304:
curl -i "http://localhost:8000/api/v1/events?city=Уфа" \
     -H 'If-None-Match: "<значение_etag_из_первого_запроса>"'
```

### 3. Карточка события по идентификатору:
```bash
curl -X GET "http://localhost:8000/api/v1/events/2b26dc3d-fbf8-4580-b30f-94ea59e5f268" \
     -H "Accept: application/json"
```

### 4. Объяснение причин пустой выдачи (ТЗ 6.1):
```bash
curl -X GET "http://localhost:8000/api/v1/events/explain-empty?city=Сибай&category=балет" \
     -H "Accept: application/json"
```

### 5. Справочники городов и категорий:
```bash
curl -X GET "http://localhost:8000/api/v1/cities"
curl -X GET "http://localhost:8000/api/v1/categories"
```

### 6. Создание подписки без PII:
```bash
curl -X POST "http://localhost:8000/api/v1/subscriptions" \
     -H "Content-Type: application/json" \
     -d '{"telegram_id": "123456789", "city": "Уфа", "category": "концерт"}'
```

### 7. Мониторинг доступности (`/health`) и метрики (`/metrics`):
```bash
curl -X GET "http://localhost:8000/health"
curl -X GET "http://localhost:8000/metrics"
```
