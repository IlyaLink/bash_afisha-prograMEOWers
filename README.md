# Сервис «Афиша культуры Башкортостана»

> **Юридический дисклеймер**:  
> *Сервис является независимым информационным агрегатором и не является официальным сайтом Министерства культуры Республики Башкортостан.*

Проект разработан для хакатона в строгом соответствии с Техническим заданием (`doc-1794511459.pdf`).

---

## 1. Выбранный объём решения
* **Выбранный уровень**: **Уровень 2 («Сайт», 60 баллов)**.
* **Включает в себя**:
  * **Общие требования (ТЗ 6.1)**: Реляционная база данных (PostgreSQL 16), раздельное хранение нормализованных данных (`events`) и сырых записей (`raw_events`), справочники городов и категорий, 100% идемпотентный импорт CSV/JSON с детальным отчётом, дедупликация со сведением дублей из разных источников в единую карточку со списком подтверждённых источников, журнал изменений `audit_logs` (кто, когда и что изменил), скрытие отменённых событий из каталога с отображением яркой предупреждающей плашки по прямой ссылке.
  * **Уровень 1 (ТЗ 6.2)**: Telegram-бот на aiogram 3.x в отдельном Docker-контейнере, работающий через REST API бэкенда (`httpx.AsyncClient`), поиск по фильтрам и свободному тексту, инлайн-пагинация («Показать ещё ⏩»), подписка и отписка одной командой, отсутствие навязчивых уведомлений.
  * **Уровень 2 (ТЗ 6.3)**: Адаптивный веб-каталог от 360px на HTMX и Tailwind CSS (CDN) без отдельных Node.js/npm сборщиков, синхронизация фильтров с URL-параметрами, постоянные ссылки на карточки `/events/{id}` (до 3 кликов от входа), встраиваемый изолированный виджет `/widget` для `<iframe>` без сторонних cookies, защищённая форма обратной связи для организаторов (с защитой honeypot и rate-limiting), веб-админка с модерацией и импортом, версионированный REST API `/api/v1/` с OpenAPI 3.1 (`/docs`), ETag-кешированием, структурным JSON-логированием со сквозным `request_id` без персональных данных, эндпоинтом `/health` и базовыми метриками `/metrics`.
* **Исключено**: Функционал Уровней 3 и 4 (ИИ-агент, LLM-интеграции, внешние парсеры сайтов).

---

## 2. Стек технологий
* **Backend & Web**: Python 3.11+, FastAPI, Jinja2, HTMX, Tailwind CSS (через официальный CDN). Монолитное, быстрое развертывание из Python-контейнера.
* **База данных & ORM**: PostgreSQL 16, SQLAlchemy 2.0 (asyncio, asyncpg), Alembic (миграции), SQLite fallback для мгновенного локального запуска.
* **Telegram-бот**: Python 3.11+, aiogram 3.x (работает в отдельном контейнере, ходит в бэкенд по REST API).
* **Инфраструктура**: Docker, `docker-compose.yml`, healthcheck, автоприменение миграций и сидинг 30+ событий при первом старте.

## 3. Быстрый запуск одной командой

### Вариант 1: Запуск через Docker Compose (рекомендуемый)
Убедитесь, что Docker запущен, и выполните в корне проекта:
```bash
docker compose up --build
```
Сервис автоматически:
1. Запустит PostgreSQL 16 и проверит healthcheck (`pg_isready`).
2. Применит все миграции базы данных Alembic (`alembic upgrade head`).
3. Загрузит базовые справочники и **31 реальное культурное мероприятие по Башкортостану** (включая бесплатные, детские, на башкирском языке, дубликат и отменённый спектакль).
4. Запустит веб-сервис на порту `8000` и Telegram-бота.

Сервис готов к работе по адресу: **http://localhost:8000**  
Интерактивная документация Swagger: **http://localhost:8000/docs**  
Админ-панель: **http://localhost:8000/admin** (Логин: `admin`, Пароль: `culture_bashkortostan_2026`)

---

### Вариант 2: Локальный запуск без Docker (на Python 3.11+)
```bash
# 1. Создание виртуального окружения и установка зависимостей
python -m venv .venv
source .venv/bin/activate  # на Windows: .\.venv\Scripts\activate
pip install -r requirements.txt
pip install -r requirements-bot.txt

# 2. Применение миграций и наполнение тестовыми данными
alembic upgrade head
python -m scripts.seed_data

# 3. Запуск веб-сервера
uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```

## 4. Сценарий демонстрации на 5 минут (по шагам)

### Шаг 1. Веб-каталог и синхронизация URL (1 минута)
1. Откройте главную страницу `http://localhost:8000`.
2. Обратите внимание на **обязательный юридический дисклеймер** в верхней плашке и подвале сайта.
3. В фильтре выберите город **«Стерлитамак»** или категорию **«Концерт»** — каталог мгновенно обновляется через **HTMX** без перезагрузки страницы.
4. Обратите внимание на адресную строку браузера: URL автоматически обновляется (`/?city=Стерлитамак&category=концерт`). Скопируйте ссылку и откройте в новой вкладке — состояние фильтров сохраняется полностью!
5. Попробуйте ввести поисковый запрос (например: *«джаз»* или *«кукольный»*) — моментальный поиск по нормализованным названиям и описаниям.
6. Выберите заведомо отсутствующую комбинацию (например, г. Салават + цена 0 руб.) — сайт отобразит понятный разбор причин отсутствия событий и подскажет, какое ограничение стоит ослабить (ТЗ 6.1).

### Шаг 2. Карточка события и дедупликация источников (1 минута)
1. Нажмите на карточку **«Балет «Лебединое озеро»»** в Уфе.
2. Проверьте путь пользователя: переход на карточку `/events/{id}` осуществляется в 1 клик от главной страницы.
3. Внизу карточки обратите внимание на блок **«Подтверждённые источники данных»**: отображаются ссылки на первоисточники мероприятия, подтверждающие отсутствие выдуманных событий.

### Шаг 3. Обработка отменённого события (45 секунд)
1. В каталоге отменённые события скрыты (ТЗ 6.1).
2. Перейдите по прямой ссылке на отменённый спектакль:  
   Найдите его в админке или откройте карточку спектакля «Карагул» в г. Сибай.
3. В самом верху карточки отображается **крупная яркая красная плашка**:
   *«Внимание! Мероприятие отменено организатором! Данное событие снято с репертуара учреждением культуры...»*

### Шаг 4. Встраиваемый виджет для сайтов (30 секунд)
1. Откройте страницу `http://localhost:8000/widget?city=Уфа`.
2. Это автономный, легковесный виджет для `<iframe>`, готовый к встраиванию на официальный портал Министерства культуры РБ.
3. Виджет изолирован, адаптивен под любую ширину и работает без сторонних cookies (ТЗ 6.3).

### Шаг 5. Админ-панель, идемпотентный импорт и аудит (1 минута)
1. Перейдите в `http://localhost:8000/admin`.
2. Введите учетные данные (логин `admin`, пароль `culture_bashkortostan_2026`).
3. **Проверка дедупликации**:
   - В форме импорта выберите файл `data/events_duplicate.json` и нажмите «Запустить импорт».
   - Система выдаст отчёт: `Добавлено: 0`, `Сведено дублей: 1`! Карточка спектакля «Лебединое озеро» не продублировалась, а объединила источники.
4. **Проверка идемпотентности**:
   - Загрузите `data/events_seed.json` повторно. Отчёт: `Добавлено: 0`, `Обновлено: 0`. Ни одного дубля!
5. **Модерация**:
   - В таблице событий нажмите кнопку «Снять (отмена)» у любого мероприятия — его статус мгновенно изменится на «отменено», и оно исчезнет из общего каталога.
6. **Журнал изменений**:
   - В таблице «Audit Logs» зафиксированы все операции: кто, когда, какую запись и как изменил.

### Шаг 6. Telegram-бот (45 секунд)
1. Бот запущен в контейнере `afisha_bot`. При указании реального `BOT_TOKEN` в `.env`:
2. Отправьте команду `/start` — компактное меню на инлайн-кнопках без простыней текста.
3. Нажмите «📅 Сегодня» или «🎟 Бесплатные» — бот пришлет карточки с кнопкой «Купить билет / Источник» и кнопкой пагинации **«Показать ещё ⏩»**.
4. Напишите любое слово в чат (например: *«курай»* или *«опера»*) — свободный текст мгновенно ищет события в базе.
5. Нажмите «🔔 Мои подписки» -> «➕ Подписаться на город» -> «Уфа» — подписка оформлена без сбора персональных данных.
6. Отправьте `/unsubscribe` — моментальная отписка одной командой.

## 5. Открытый контракт REST API (`/api/v1/`)

Интерактивная спецификация OpenAPI 3.1 доступна по адресу: **http://localhost:8000/docs**

### Примеры запросов curl:

**1. Получение списка событий с фильтрацией и пагинацией:**
```bash
curl -X GET "http://localhost:8000/api/v1/events?city=Уфа&category=концерт&page=1&size=5" \
     -H "Accept: application/json"
```

**2. Проверка ETag-кеширования (получение 304 Not Modified):**
```bash
# Первый запрос: получаем ETag
curl -i "http://localhost:8000/api/v1/events"

# Второй запрос: передаем If-None-Match
curl -i "http://localhost:8000/api/v1/events" \
     -H 'If-None-Match: "c0b7...d21"'
```

**3. Проверка здоровья сервиса и базы данных:**
```bash
curl -X GET "http://localhost:8000/health"
```
Ответ:
```json
{
  "status": "ok",
  "database": "healthy",
  "version": "1.0.0",
  "environment": "production"
}
```

**4. Базовые метрики сервиса:**
```bash
curl -X GET "http://localhost:8000/metrics"
```

**5. Оформление подписки в Telegram (без PII):**
```bash
curl -X POST "http://localhost:8000/api/v1/subscriptions" \
     -H "Content-Type: application/json" \
     -d '{"telegram_id": "123456789", "city": "Уфа", "category": "спектакль"}'
```

**6. Отправка обращения организатора (с защитой от спама):**
```bash
curl -X POST "http://localhost:8000/api/v1/feedback" \
     -H "Content-Type: application/json" \
     -d '{
       "organizer_name": "Башкирский театр драмы",
       "contact": "info@bashdram.ru",
       "message": "Просим обновить время начала спектакля 21 ноября на 18:30"
     }'
```

## 7. Политика конфиденциальности и минимизация данных
* Персональные данные пользователей не собираются: в подписках сохраняются только анонимный `telegram_id` и выбранные фильтры.
* В системных логах отсутствует PII (IP-адреса маскируются, чувствительные заголовки не пишутся).
* Срок хранения неактивных подписок: 180 дней. Пользователь может удалить все данные одной командой `/unsubscribe`.
